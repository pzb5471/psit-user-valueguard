# 使用浏览器 ZIP 上传，并限制一个活动批次

工作台通过浏览器上传一个标准案例 ZIP，不让用户填写服务器文件路径，也不把固定案例直接写入数据库。上传内容先进入批次专用临时目录；系统完成 ZIP 安全、Schema、禁用字段、重复标识、资源路径和校验值检查后，才原子移入正式目录并写入 SQLite。仓库中的固定演示包与验收包也必须经过同一入口。

同一时间只允许一个活动批次。用户尝试启动第二个批次时，系统返回当前活动批次编号；新批次继续保持待分析，不进入自动队列，也不会在前一批结束后自行产生模型调用。不同批次的案例不混合排序，页面默认显示最近导入批次，并允许切换历史批次。

这一限制降低并行演示能力，但能在单进程、SQLite 和共享 API 额度下保持状态与费用可控。允许多个活动批次会新增跨批次调度、公平性、成本上限和恢复规则；自动排队又会违反每次模型调用必须由用户明确触发的门禁。
