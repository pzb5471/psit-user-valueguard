# 使用分类型证据和有依据的 PerceptionResult

`CaseInput v1.evidence` 固定包含 `text_items`、`image_items` 和 `behavior_items` 三个数组，不把不同模态塞进一个无约束通用列表。所有证据共同保存 `evidence_id`、`identity`、`relation_identity`、`source_ref` 和 `content_hash`。文本证据增加顺序、说话方和脱敏文本；图片证据增加资源路径、媒体类型、文件哈希和原始来源；行为证据增加事实类型、值、来源字段，以及派生事实确实需要时才出现的计算规则。时间只在对应源数据实际提供时保存，不要求每条证据携带空 `occurred_at`。证据编号由组包程序生成，在同一案例重跑时保持不变，Agent 只能引用已有编号。

感知阶段以消息顺序还原事件。每个事件只保存事件编号、事件类别、摘要、陈述状态、解决状态、支持证据，以及实际存在时才出现的冲突证据和不确定性。证据编号已经能够定位消息，不再重复保存消息顺序范围。陈述状态区分客户声称、客服陈述或承诺、客户确认结果、图片直接观察和程序派生事实；解决状态只允许已解决、未解决和无法确认。客服说“已经退款”不等于退款已经完成，只有后续客户确认或其他有效证据才能将结果视为确认完成。

每张输入图片必须形成一条 `ImageObservation`，只保存图片证据编号、分析状态、最多三条可观察事实、与客户陈述的关系、关联文本证据和按需出现的不确定性。关系只允许相互支持、相互冲突、补充信息和无法判断。v1 不要求模型填写主体或场景分类、固定异常类型、异常位置和可见程度。无法识别时允许使用证据不足或无法判断，不强迫模型寻找异常；图片没有拍到某个对象不能证明现实中不存在该对象，也不得根据配套文字反向补写图片内容。

客户价值和经过固定案例人工核验后允许进入 Agent 的订单事实由确定性程序生成只读行为证据，模型不得修改数值或重新计算 RFM。GLM 只负责在事件、风险原因和策略中引用相关证据，不重复输出一份 `BehaviorObservation`。当前数据无法稳定形成多个行为窗口，因此 v1 不设计行为变化字段。

`PerceptionResult` 顶层只保存 `schema_version`、`case_id`、`events`、`image_observations`、`emotion` 和 `missing_evidence`。不再重复保存文本观察、行为观察、独立证据对齐、备选解释和通用警告数组。`emotion` 只保存平静、不耐烦或无法判断、简短解释、客户文本证据，以及按需出现的不确定性；情绪变化和目标情绪不进入 v1 必填合同。所有证据引用必须存在于 `CaseInput v1`，没有来源时间时事件不得生成具体时间。

这一合同只保留下游页面、归因和人工复核实际使用的内容。删去重复字段会降低首次结构校验失败和空洞占位文本的概率；需要表达的冲突、不确定性和证据缺失仍有明确位置。本期不加入情绪分数、概率、图片坐标、检测框、Embedding 和特征向量。
