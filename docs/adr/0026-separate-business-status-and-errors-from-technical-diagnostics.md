# 分离业务状态、业务错误与技术诊断

业务页面只显示待分析、分析中、待人工确认、已完成和处理异常五种案例状态，以及总案例数、分析完成数和处理异常数。感知、归因、策略等内部阶段保存在运行记录中，不在页面展示；模型代码、Prompt、Token、参数和调用日志同样不对运营人员开放。

导入或运行失败时，页面返回中文错误摘要、失败对象、失败环节、稳定错误编号和允许的下一步。例如图片无法读取时显示案例编号、案例包内相对文件路径、`IMAGE_UNREADABLE` 和“检查案例包后重新分析”。模型供应商原始响应、SDK 错误、程序堆栈、请求参数、API Key 和本机绝对路径只保存到内部技术记录。

完全隐藏错误会让用户无法处理问题，直接展示原始异常又会泄露技术细节并造成误解。分层错误合同增加一套错误编号映射，但能让业务操作和开发排障各自获得必要信息。
