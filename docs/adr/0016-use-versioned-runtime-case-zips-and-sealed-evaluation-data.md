# 使用固定版本的运行案例 ZIP，并物理隔离验收答案

当前 `data_with_context.csv` 固定为 `mock_dataset_v1` 数据快照，不再重新运行包含随机抽样、十倍扩增和随机打乱逻辑的旧 Notebook。该 CSV 中同一张图片会被分配给多个不同订单，最多涉及 10 个订单，因此订单、售后对话和图片的组合关系统一标记为 `mock_mapped`。组合关系只用于验证产品流程，不代表真实客户或真实订单关系。生成案例包时保存 CSV、JSONL 和所有被引用图片的文件校验值；任何数据或映射变化都创建新数据版本，不覆盖旧版本。

工作台只接收一个标准案例 ZIP。ZIP 根目录包含 `manifest.json`、`cases/`、`assets/` 和 `checksums.json`；`cases/` 中每个案例保存一份独立 `CaseInput v1`，`assets/` 只复制所选案例实际引用的图片，清单和案例通过相对路径引用文件。原始大 CSV、完整图片库和验收参考答案不进入运行 ZIP。

组包程序丢弃 CSV 中无字段名的旧索引列，把 `image_paths` 从 Python 列表字符串转换为标准 JSON 数组，并按照文件真实内容而不是现有扩展名识别图片格式。普通 JPG、JPEG、PNG 原样使用并生成规范文件名；GIF 保留原文件，同时提取静态首帧作为模型输入。现有被引用图片共 92 张，均能在本地找到，文件大小约 4.3KB 至 1.79MB，因此第一版不统一压缩图片。

运行输入和验收答案生成两个物理分离的产物。运行案例包不得包含 `mood`、`reason`、`solution`、`image_verification`、`key_answer`、`label`、`database_gt`、`trajectory`、`user_profile_st1`、`user_profile`、`question_type` 等答案或答案泄漏字段，未规范化的 `user_address`、`database` 和重复的 `first_query` 也不得进入。产品导入器在任意层级发现这些字段时拒绝导入。验收参考包只允许测试程序读取，不放进产品运行目录，也不发送给任何 Agent。

项目固定提供互不重叠的 `mvp_batch_v1` 10 个案例和 `acceptance_batch_v1` 5 个案例。两批均覆盖三种介入等级、图文相互支持、图文冲突、正常模态缺失和证据不足；验收批参考答案单独密封。故意损坏的 JSON、缺失图片和不支持格式只作为技术故障测试夹具，不混入正常演示批次。

冻结随机 Mock 映射只能保证复现性，不能提高数据的真实业务效度。该选择接受这一限制，以换取当前 MVP 的稳定演示、回归测试和团队并行开发；任何文档、页面或汇报不得用这些案例声称真实流失预测准确率、真实客户关系或实际业务效果。
