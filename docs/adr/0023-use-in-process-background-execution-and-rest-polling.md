# 使用进程内后台执行和 REST 轮询

运营人员启动批量分析后，FastAPI 立即返回更新后的批次业务视图，不让一个 HTTP 请求等待整个批次，也不向页面返回内部运行编号。`RunService` 使用应用进程拥有的后台执行器处理案例，默认并发数为 2；案例状态、阶段结果和失败原因持续写入 SQLite。页面在存在活动批次时每 2 秒读取一次批次与案例状态，批次结束后停止查询。

批次开始后全部案例立即进入队列。待分析、分析中、待人工确认和处理异常可以同时出现；一个案例完成后立即开放详情和人工确认，不等待整批结束。v1 不提供停止或取消按钮。正常关闭时拒绝新任务、取消未开始任务，并让正在进行的模型请求返回或超时后停止进入下一阶段；强制退出后，下次启动把本地遗留活动运行标为 `INTERRUPTED`，把未形成完整结果的案例标记为 `APP_INTERRUPTED`，由运营人员重新分析。

当前每批最多 20 个案例、单机运行、并发很低，因此不引入 Redis、Celery 或独立 Worker，也不使用 WebSocket 或 SSE。代价是应用进程退出后后台任务不能继续；持续保存阶段结果、明确失败状态和人工重试足以覆盖本期恢复要求。FastAPI 交付运行时只启动一个服务进程，避免多个进程各自创建后台执行器。
