# 使用四种严格区分的人工确认请求

直接通过、修改后通过、驳回并给出判断、证据不足需要不同必填字段。一个包含大量可选字段的请求无法可靠阻止“修改无原因”“驳回无判断”或“通过时偷偷提交另一份结果”。

人工确认以 `outcome` 为 Pydantic 区分字段。`APPROVED` 只提交幂等编号和审核 Token；修改与驳回提交完整人工最终介入等级、原因、目录内动作和必填原因；证据不足只提交必填证据缺口说明。相同 `submission_id` 返回已有结果，旧 `review_token` 返回 `STALE_CASE_RESULT`。

不使用 JSON Patch、任意内部 JSON 编辑或一套充满可选字段的通用请求。人工动作最多三项并受当前动作目录约束。
