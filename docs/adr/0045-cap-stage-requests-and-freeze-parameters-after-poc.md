# 每阶段最多四次请求，正式参数经 PoC 冻结

> 演讲版 MVP 的双人复核条款已由 ADR 0087 取代；本 ADR 的请求上限、自动 PoC 和参数冻结规则继续有效。

关闭 SDK 自动重试，由 `RunService` 统一控制。连接中断、读取超时、HTTP 429 和 HTTP 5xx 最多重试两次；401、403、请求参数、图片格式、图片大小和输入合同错误不重试。每阶段供应商请求硬上限为四次：首次一次、可重试网络故障最多两次、收到不合格结果后的定向修复最多一次。修复请求本身发生网络错误后不继续重试。

PoC 初始配置为 `stream=false`、`response_format={"type":"json_object"}`、`thinking.type=enabled`、`reasoning_effort=high`、`do_sample=false`、`max_tokens=4096`、连接超时 10 秒、完整响应上限 300 秒、案例并发 2。这些数值只是起跑配置，不是最佳参数或验收结论。

PoC 使用固定 10 个演示案例和密封 5 个验收案例，记录 JSON 首次与修复后通过率、各阶段失败率、阶段和案例耗时、Token、每案例调用次数及图片贡献；比较 `reasoning_effort=high` 与 `max`，并比较并发 1、2、3 的 429、超时和 SQLite 写入表现。密封答案只由测试程序评分，不进入模型上下文。完成后再冻结正式超时、推理强度、默认并发和内部成本预警线。

正式配置必须满足固定案例硬门槛：45 个阶段结果首次结构通过不少于 41 个，允许修复后 45 个全部合格；不存在跨案例或虚假证据引用、目录外动作和隐藏答案泄漏；5 个密封验收案例全部被两名验收者判断为可作为决策初稿；两个图片贡献案例和一个行为贡献案例均达到规定差异。默认并发 2 时，第一个完整案例目标在 2 分钟内出现，10 个演示案例目标在 10 分钟内完成，且不得持续触发 429 或 SQLite 写入错误。

这些门槛只证明当前固定案例可运行，不代表真实业务准确率。未通过时依次检查输入与证据、Prompt、合同与校验器，再比较 `high/max` 和并发配置；不得删除失败案例、修改密封答案迎合模型、把答案放入 Prompt、放宽证据规则或使用预写结果。仍未通过时明确判定当前模型路线未达到可用 MVP 门槛。
