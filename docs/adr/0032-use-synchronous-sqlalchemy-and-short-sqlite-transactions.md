# 使用同步 SQLAlchemy 和 SQLite 短事务

后端使用同步版 SQLAlchemy 2 和 Alembic。每个 FastAPI 请求、每个后台案例任务创建自己的 Session，不在线程或任务之间共享 Session。调用 GLM 前先提交或回滚当前事务，等待模型返回期间不占用数据库事务；模型响应通过结构校验后，再使用短事务保存调用记录、阶段结果和状态变化。

SQLite 启用外键约束、WAL 模式和 5 秒 `busy_timeout`。数据库约束保证全系统最多一个状态为启动中或分析中的 `batch_run`，并保证同一案例最多一个活动 `case_run`。应用层锁和页面按钮禁用可以减少重复操作，但不能代替数据库最终约束。

同步实现适合当前单进程、案例并发初始为 2 的规模，也与直接使用 GLM SDK 的运行方式一致。`aiosqlite`、共享全局 Session、跨模型调用的长事务和独立数据库服务都会增加复杂度，却没有当前负载证据支持。
