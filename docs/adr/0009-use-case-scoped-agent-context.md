# Agent 使用封闭的案例级上下文

每次 Agent 调用只允许读取从当前 `CaseInput v1` 生成的阶段受限视图。感知 Agent 读取当前案例对话、图片、经过人工核验的订单状态和履约事实，以及可引用证据编号；不读取高价值客户结论、RFM、风险答案和动作目录。归因 Agent 读取 `PerceptionResult`、其中实际引用的客户文本和订单事实、图片观察及证据编号；不重复发送原图，也不读取高价值结论和动作目录。策略 Agent 读取 `PerceptionResult`、`AttributionResult`、高价值客户结论、获准证据编号、动作目录和介入等级最低规则；不读取原始图片、完整原始对话或 RFM 过程。高价值结论只影响介入优先级和处理方式，不反向影响事件、情绪和风险原因。

完整 `CaseInput v1` 可以保存内部 RFM 结果和百分位分界用于复算，但任何 Agent 都不读取 RFM 分数、阈值或计算过程。由于当前订单、售后对话和图片属于 `mock_mapped` 组合，订单和履约事实只有在固定案例经过人工检查、确认与对话语义不冲突后才发送给 Agent；源数据未提供币种，付款金额不进入模型判断。客户标识、城市、州和邮编同样不进入模型上下文。

`solution`、`mood`、`reason`、`image_verification`、`key_answer`、`label`、`database_gt`、`trajectory`、`user_profile_st1`、`user_profile`、`question_type` 及后来形成的人工参考答案全部保存在独立验收区，不进入案例包，也不允许任何运行 Agent 读取。未规范化的 `user_address`、`database` 和重复的 `first_query` 同样不进入运行包。Agent 也不得读取其他案例结果、任意项目文件、互联网搜索结果或跨运行自由文本记忆。同一批次中的案例彼此独立，批次只共享数据版本、确定性 RFM 口径、策略范围和运行配置。这样选择牺牲了开放式检索和跨案例联想，但能够保证结论可追溯、案例可并行、失败可单独重试，并降低模拟数据、外部信息和隐藏答案相互污染的风险。
