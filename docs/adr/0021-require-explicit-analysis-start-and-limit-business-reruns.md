# 批次导入后显式开始分析，并限制业务重新分析

标准案例 ZIP 完成原子校验和导入后，所有案例先进入待分析状态。页面展示批次编号、案例数、图片数、数据版本和 Mock 标记；只有运营人员明确执行一次“开始批量分析”后，`RunService` 才为该批次创建运行并调用 GLM。导入、刷新页面和应用重启都不得自动产生付费模型调用。

案例业务状态只使用待分析、分析中、待人工确认、已完成和处理异常。处理异常和待人工确认案例可以重新分析，每次创建新的 `run` 并保留旧阶段结果和失败原因；已完成人工确认的案例在业务页面保持只读，不提供重新分析入口。开发测试工具可以创建独立运行版本，但不能改变已有人工结果。

该选择增加一次明确操作，但避免错误批次、重复导入和程序重启直接消耗 API 额度，也避免已完成业务记录因为新模型结果重新进入待确认。逐例勾选后启动虽然控制更细，但会增加队列选择、部分批次状态和批量操作逻辑，不进入 v1。
