# RFM 判断客户价值，不直接决定案例风险

现有清洗流程中按客户聚合订单、计算 RFM、形成高价值客户候选池的方法继续作为产品数据层的基线。当前数据共有 96,095 名客户，其中 93,098 名只有一张订单，F、M 分布明显长尾，因此现有绝对阈值只作为历史结果对照。

MVP 使用相对规则 `high_value_rule_v1`：`R <= P75(R) AND (M >= P80(M) OR (F >= 2 AND M >= P50(M)))`。百分位在当前客户级数据快照上计算，边界并列客户全部纳入，实际分界值与数据版本一起保存。当前快照对应 `P75(R)=397`、`P80(M)=209.60`、`P50(M)=108.00`，得到 15,208 名高价值客户、2,538 张具有售后对话的候选订单，以及 390 张同时具有对话和图片的候选订单。上游保存 R、F、M、计算日期、判定结果、判定理由、百分位分界和规则版本；Agent 不重新计算，业务页面不展示分数、权重和阈值。该规则用于保证 Mock 数据环境可复现，不代表已经获得真实企业验证。

RFM 只回答“哪些客户具有较高的相对交易价值”，不能单独决定售后案例是否需要介入。正式业务队列只接收达到高价值规则且具有明确售后对话或投诉描述的案例；事件严重程度、紧迫性、当前情绪和证据状态共同决定介入等级。当前数据不能稳定形成行为变化比较，v1 不使用消费下降或频次下降。普通客户只作为开发与验收对照。现有 80% 多模态分配比例不作为产品规则，标准案例选择以覆盖验收分支和来源可追溯为准。
