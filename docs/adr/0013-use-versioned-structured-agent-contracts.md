# Agent 之间使用版本化结构合同

MVP 不把 Agent 返回的任意长文本直接交给下一阶段、页面或正式数据库。运行链固定使用 `CaseInput v1`、`PerceptionResult`、`AttributionResult` 和 `DecisionPackage` 四份版本化结构合同。`PerceptionResult` 只保存事件、逐图片观察、当前情绪和缺失证据；`AttributionResult` 保存一句风险结论、一个主要原因、支持证据，以及按需出现的反证、不确定性和最多一个备选原因；`DecisionPackage` 保存介入等级、排序理由、批准范围内的处理动作、沟通重点和按需出现的注意事项。

文本、图片和行为证据分别形成可定位的 `evidence_id`。事件、原因和处理方案中的重要判断必须引用至少一个证据 ID，并将观察事实与系统推断分开。业务页面从校验通过的结构字段生成业务可读内容；原始模型响应只作为内部运行记录，不成为正式业务结果。

固定合同增加了字段设计和升级成本，但允许三个 Agent 由不同成员并行开发，支持独立测试、失败定位、受控重试和结果持久化。合同只保留下游实际使用的字段，不要求模型重复程序已有事实，不用空数组或套话填充本案例不存在的内容。Pydantic 模型是字段结构的唯一来源，运行时由程序生成 JSON Schema 并注入对应阶段 Prompt，不再手工维护第二份字段清单。Prompt 分别保存在 `prompts/perception/v1.md`、`prompts/attribution/v1.md`、`prompts/strategy/v1.md`，每次调用记录语义版本和文件 SHA-256。

模型调用启用 JSON 输出模式；程序仍必须用 Pydantic 严格模式对返回值做本地校验，未声明字段直接拒绝，不做字符串、列表或数字之间的宽松转换。自由文本串联虽然搭建更快，却无法稳定判断字段缺失、答案泄漏、证据来源和下游兼容性，因此不采用。
