# 演讲版 MVP 采用项目负责人多轮演示验收

## 状态

已接受，2026-09-11。

## 背景

ADR 0045 与 ADR 0046 最初把两名业务验收者复核 5 个密封案例设为生产分析开放条件。随后项目已经对 GLM-5.3-Flash 完成五轮固定 15 案例真实 PoC，最终自动门为 15/15 案例、45/45 阶段通过，并完成确定性浏览器、真实 HTTP/SQLite 与生产启动验证。项目负责人明确确认已经进行过多轮结果检查，不再为演讲 Pre 重复执行双人复核；当前交付目标是可由仓库直接运行和演示的核心链路验证 MVP，不是企业生产准确率认证。

## 决策

- 演讲版 MVP 以项目负责人基于多轮真实运行记录的验收作为发布依据，双人复核表不再是启用真实分析、PR 合并或演示的硬门槛。
- M2-10 的自动硬门继续保留：固定 15 个案例和 45 个阶段必须完整运行，结构、证据、动作、答案隔离、耗时、Token 与失败记录必须可复算。
- `analysis.production_enabled` 默认设为 `true`；仍然只有同时提供 `ZAI_API_KEY` 时才装配真实 `GlmClient`，缺少密钥时继续安全关闭分析并允许读取历史结果。
- 仓库提交脱敏且通过正式导入器的 `demo/demo_batch_v1.zip`，使演讲环境不依赖私有源数据即可完成固定 10 案例演示。私有源数据、验收参考答案、运行数据库和 API Key 仍不得进入 Git。
- 原双人复核表保留为未来业务试点或课程团队希望增加人工质量检查时的可选模板，不再出现在当前合并清单中。

## 后果

本决策只证明演讲环境中的固定案例核心链路可运行，不能用于声称真实业务准确率、客户留存提升、ROI 或企业生产可用性。以后进入真实业务试点时，需要重新定义样本、验收者和业务质量门，不能把本次项目负责人演示验收直接外推。
