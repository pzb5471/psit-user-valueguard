# 使用模块优先的单仓库和单向依赖

项目由四名成员并行开发。单纯按照 `api/services/models` 横向分层会让每个功能同时跨越多人目录，造成大量同文件冲突；四个完全独立仓库又会增加合同同步和本机启动成本。

项目使用一个仓库，后端按 `data`、`analysis`、`application` 三个业务模块组织，前端构成第四个模块。纯共享合同位于独立合同目录，但不承载业务实现，也不算第五个模块。M4 只调用 M3，M3 通过公开接口调用 M1 和 M2，M1 与 M2 互不调用，共享合同不反向依赖模块。

不采用四仓库、不按技术层把四个人拆成数据库、接口、组件和测试专员，也不允许跨模块传递 ORM、SDK 响应或前端状态对象。模块内部可以继续分层，但文件主归属首先服从四模块边界。
