# 程序执行介入底线和动作目录，人工采用结构化确认

Strategy Agent 负责提出系统建议介入等级、排序理由和处理动作，确定性程序负责执行最低介入等级。未解决的明显损失、严重履约异常、商品损坏、错漏发、未到货和退货退款争议不能成为“暂不介入”；严重问题存在证据冲突或证据不足时至少为“建议介入并人工核验”。只有问题已确认解决或没有可执行风险事项时，才允许“暂不介入”。高价值客户身份本身不能单独触发“必须介入”。

Agent 等级低于最低要求时，程序直接采用最低允许等级并在内部运行记录保存原值、最终值和调整原因，不再次调用模型，也不改写风险原因或处理动作。业务页面显示最终系统建议等级和能够理解的调整理由，模型原始响应保留在内部记录。

六类批准动作保存在只读、版本化的 `action_catalog.v1.json`，后端启动时校验结构、动作代码唯一性和禁止内容。每个决策包最多选择三项动作，并保存动作目录版本。MVP 不把目录写死在三个 Agent 中，也不建设动作管理页面。

人工确认使用结构化表单。全部认可时一键通过；介入等级只能从三档中重选，风险原因只能从六类中重选，处理方案只能增删批准动作并填写一段执行说明。任何修改或驳回都必须填写原因；驳回还必须补充最终人工判断或标记证据不足。页面不开放任意编辑内部 JSON，系统原结果与人工结果分别追加保存。

最强反对意见是固定底线可能削弱 Agent 的自主判断。该意见力度为中等。底线只阻止明显低估和越权动作，事件理解、风险归因、证据解释和具体建议仍由 Agent 完成；完全让模型决定会提高同案结果漂移和错误放行风险。
