# 使用 URL 状态和有边界的 TanStack Query 轮询

批次与案例地址必须能刷新恢复，分析进度又需要在没有 WebSocket 的本机 MVP 中持续更新。若把业务结果保存到浏览器或让多个组件各自创建计时器，页面会出现旧结果、重复请求和跨批次污染。

当前批次、当前案例和筛选条件保存在 URL；FastAPI 与 SQLite 是业务事实真源，TanStack Query 只管理服务端状态缓存。活动批次每 2 秒轮询，终态停止，页面在后台时暂停，回到前台立即刷新。写操作只使相关查询失效。

不使用 `localStorage` 保存或覆盖业务事实，不建立 Redux 或 Zustand 业务镜像，不让页面组件各自维护无边界轮询，也不在终态和后台继续发送定时请求。
