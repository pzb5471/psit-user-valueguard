# 产品运行时大模型采用 GLM-5.3-Flash

MVP 的感知、归因和策略三个 Agent 统一调用智谱模型 `glm-5.3-flash`。这里把“动态模型”明确为产品处理每个案例时实际调用的运行时大模型；RFM、高价值客户判定、支付汇总、字段检查、枚举约束和排序规则仍由确定性程序执行，不交给大模型计算。Claude 或 Claude Code Agent Teams 不进入产品运行链路，只能作为开发协作工具。

FastAPI 后端通过固定版本的智谱官方 `zai-sdk` 直接调用通用 Chat Completions API，不使用智谱 Agent API、GLM Coding Plan 专属端点或第三方 Agent 编排平台。项目内只保留一个薄的 `GlmClient` 接入模块，统一处理模型代码、鉴权、请求组装、超时、重试、响应解析、请求标识和用量记录；三个 Agent 不得分别编写网络调用。API Key 从本机环境变量 `ZAI_API_KEY` 读取，不进入前端、案例包、数据库、日志或代码仓库。

`glm-5.3-flash` 原生支持文本和图片输入，因此第一版直接把售后对话与本地图片交给同一模型处理，不再增加独立 OCR 或图片理解模型。程序在调用前检查图片是否存在、格式是否允许、大小是否超限，再以 Base64 Data URL 传入；图片模糊、内容不可判断属于模态证据不足，文件无法读取或调用失败属于模态技术失败。只有模型 PoC 证明现有图片无法达到验收要求时，才重新评估增加专用视觉模型或 OCR。

模型调用启用 `response_format={"type":"json_object"}`，在系统提示词中写明对应版本的结构合同，返回后再由 Pydantic 做字段、类型、枚举、证据引用和禁用内容校验。JSON 模式不能替代本地结构校验；校验失败只允许一次携带具体错误的定向修复。每次运行保存模型代码、模型参数、提示词版本、结构合同版本、原始响应、校验结果和用量信息，确保问题可以复现。

统一使用一款模型可以降低成本和接入复杂度，但也会让三个阶段共享同一种能力偏差，并且该模型在本项目数据上的图片识别、结构稳定性、延迟和并发行为尚未经过验证。因此模型选择已经确定，具体超时、并发数、图片压缩规则和采样参数必须经过固定案例 PoC 后才能冻结，不能直接照抄官方推荐值。

官方依据：[GLM-5.3-Flash 模型说明](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)、[结构化输出说明](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output)。
