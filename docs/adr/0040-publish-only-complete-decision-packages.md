# 只发布完整并通过校验的决策包

感知、归因、策略三个阶段顺序执行。阶段结果通过对应 Schema 后立即保存到内部 `stage_results`，但只要三个阶段尚未全部完成，业务接口和页面就只显示分析中，不返回事件、情绪、风险原因或策略半成品。

策略结果通过 Schema、证据引用、动作目录、最大数量和最低介入等级等程序规则后，服务层在一个事务中保存最终阶段结果、更新 `case_run`、切换 `cases.current_case_run_id` 并把案例置为待人工确认。随后业务 DTO 才能一次性发布高价值结论、流失风险原因和处理建议。

后续阶段失败时，案例进入处理异常并显示业务可处理错误。已经完成的内部阶段仍保存在数据库供开发排障和允许的重新分析使用，但不进入业务 DTO。逐阶段展示看似更“智能”，实际会向运营人员提供尚不能采取行动且可能被后续推翻的信息。
