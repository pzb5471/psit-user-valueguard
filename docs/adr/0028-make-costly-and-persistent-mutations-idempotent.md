# 让付费调用和持久化写操作具备幂等性

所有可能因为重复点击或网络重试而重复付费、重复落库的操作都必须具备幂等性：

- 完全相同的 ZIP 按上传文件校验值返回已有批次；`batch_id` 全局唯一，已有 `batch_id` 对应不同内容时返回 `BATCH_ID_CONFLICT`。
- 同一批次处于分析中时再次启动，返回原运行记录，不产生新的模型调用。
- 同一案例处于重跑中时再次请求重跑，返回原重跑记录，不创建第二个运行版本。
- 人工确认携带前端生成的唯一 `submission_id` 和案例详情提供的不可读 `review_token`；相同提交编号重试返回原保存结果，旧 Token 返回 `STALE_CASE_RESULT`，使用新编号修改已完成案例时返回 `CASE_ALREADY_COMPLETED`。
- 另一个批次已经活动时，启动请求返回 `ACTIVE_BATCH_EXISTS` 和活动批次编号，新批次继续待分析。

成功响应不使用只有 `success: true` 的空结果：单项直接返回资源，列表返回 `items` 和 `total`，写操作返回保存后的业务视图，不向页面返回运行编号。错误统一返回稳定 `code`、中文 `message`、失败对象、业务可理解的 `stage`、`next_action` 和 `trace_id`。按钮禁用仍可改善操作体验，但不能代替后端幂等、审核 Token 和数据库唯一约束。
