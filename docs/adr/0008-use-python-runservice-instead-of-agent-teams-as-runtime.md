# 产品运行时由 Python 调度，不绑定 Claude Code Agent Teams

工作台的正常运行由 Python `RunService` 负责启动、阶段调度、结构校验、状态保存、失败重试和结果持久化；感知、归因和策略仍作为职责、提示词、输入输出合同及运行记录彼此独立的三个 Agent。三个 Agent 在产品运行时统一调用智谱 `glm-5.3-flash`，但保留各自独立的提示词、结构合同和运行记录。`RunService` 使用 FastAPI 单进程内的应用级后台执行器，启动请求立即返回，案例并发初始为 2。Claude Code Agent Teams 只用于团队并行开发，不进入业务人员使用工作台时的产品运行链路。这样选择是因为本期目标是可重复、可恢复、无需业务人员操作命令行的可用 MVP，而 Agent Teams 当前更适合交互式协作，直接绑定会增加会话中断、恢复和产品集成风险。

`RunService` 在模型调用前完成案例必填字段、重复标识、文件路径和隐藏答案检查。批次导入只写入待分析状态，必须收到运营人员的“开始批量分析”操作后才调用模型。每个 Agent 返回后校验固定字段、枚举、证据引用和禁用内容；结构不合格时携带具体错误进行一次定向修复，网络或模型临时故障最多重试两次。仍然失败时只将当前案例标记为处理异常，同批其他案例继续。处理异常和待人工确认案例重新分析时创建新运行版本；已完成人工确认的案例在业务页面保持只读。具体超时时间在模型 PoC 后进入配置。
