# PSIT 本机运行与启动保护

本文冻结 PSIT 本机 MVP 的运行数据位置、访问端口和单实例保护，解决"四名成员在不同电脑上能够得到同一种启动行为"。备份轮换、导入隔离区、浏览器自动打开、前端构建指纹复用和 stop.ps1 停止协议已被技术执行文档第 17 节删除或降级，本文不再包含这些设计。

## 1. 运行数据位置

默认运行数据根目录是项目根目录下的 `runtime_data/`，不得按命令行当前目录解析。成员从项目外执行 `scripts/start.ps1`，仍然只能访问同一个默认数据库。

非敏感配置采用以下两层：

1. `config/default.toml` 保存团队统一默认值并进入 Git。
2. 可选的 `config/local.toml` 保存成员电脑的显式覆盖并由 Git 忽略；仓库只提交 `config/local.example.toml`。

`storage.runtime_dir` 默认值为 `runtime_data`。相对值一律相对项目根目录解析；也允许在 `config/local.toml` 中填写本机绝对路径，为以后把数据迁移到 Windows 用户数据目录保留出口。不得使用命令行当前目录、系统临时目录、UNC 网络路径或不可写目录，也不得在失败后静默换到另一处。

程序启动时只创建和使用以下结构：

```text
<resolved_runtime_dir>/
├── psit.db
├── psit.lock
├── imports/
│   └── tmp/
├── batches/
└── logs/
```

数据库中的批次文件路径始终相对已经解析的运行数据根目录保存。技术启动输出可以显示最终绝对位置帮助团队排错，但业务 API 和页面不得返回本机绝对路径。

## 2. 本机地址和端口

演示环境默认地址为 `http://127.0.0.1:8000`，FastAPI 在同一端口提供构建后的 React 页面、`/api/v1` 和受控证据文件。开发环境默认使用：

- FastAPI：`127.0.0.1:8000`
- Vite：`127.0.0.1:5173`

端口允许通过 `config/local.toml` 显式覆盖，取值必须在 `1024—65535`，FastAPI 与 Vite 端口不得相同。启动脚本和 Vite 代理必须读取同一份已经校验的配置，不得分别写死第二套端口。

端口被占用时直接停止并显示冲突端口及处理办法，不自动选择随机端口。v1 的监听地址固定为 `127.0.0.1`，配置成 `0.0.0.0`、局域网地址或公网地址时必须拒绝启动。

## 3. 一个运行目录只允许一个应用实例

应用在接触 SQLite、迁移、恢复运行或开放 HTTP 之前，必须取得 `<resolved_runtime_dir>/psit.lock` 的操作系统级独占锁，并持有到应用进程退出。Windows 交付使用 Python 标准库 `msvcrt` 实现，不新增第三方锁依赖。

锁文件可以记录 PID、开始时间、配置端口和运行目录，供启动失败时定位；这些内容只属于本机技术诊断。判断依据必须是操作系统锁是否能够取得，不能依据文件是否存在：进程异常结束后锁文件可能仍在，但系统锁会自动释放，下次启动应当能够重新取得并覆盖诊断信息。

取得同一运行目录锁失败时，程序以 `INSTANCE_ALREADY_RUNNING` 停止，不迁移数据库、不启动执行器、不调用 GLM。两个明确配置为不同运行目录且使用不同端口的开发实例可以同时存在，但它们属于两套完全分离的数据。

## 4. 启动顺序与失败行为

`scripts/start.ps1` 按以下固定顺序执行，任何一步失败立即停止并返回非零退出状态，不回退、不静默替代：

1. 读取并校验配置、`ZAI_API_KEY` 状态、运行目录和端口。
2. 取得运行目录单实例系统锁。
3. 构建当前前端；失败停止，不提供旧页面。
4. 使用 Alembic 创建或升级数据库；失败停止，不删除或自动重建现有数据库。
5. 执行中断恢复检查。
6. 由 FastAPI 提供静态页面和 `/api/v1`。
7. 健康检查通过后在启动窗口显示实际访问地址、数据库状态和分析能力状态，由用户手工打开浏览器。

启动输出不得包含 API Key、完整客户内容、Prompt、供应商原始响应或密封答案。缺少 `ZAI_API_KEY` 不是启动失败：应用正常启动，历史批次与结果可以读取，开始分析和重新分析返回业务可理解的不可用提示。

## 5. 数据保护与正常关闭

重要演示前需要保护数据时，先停止应用，再人工复制完整 `runtime_data/` 目录。本期不建设自动备份、完整性校验、备份轮换和 `backup.ps1`。

停止只有一条入口：在启动窗口按 `Ctrl+C`。关闭流程由 M3 统一执行：

1. 拒绝新的开始和重跑请求。
2. 取消尚未开始的后台任务，并把对应运行标为中断。
3. 等待当前模型请求返回或达到已冻结超时。
4. 当前请求与记录完成后，不再开始下一阶段。
5. 已满足完整发布条件的结果正常发布；未形成完整结果的运行标为中断。
6. 关闭线程池、日志和数据库资源，释放单实例锁。

浏览器关闭不停止后台分析；强制结束进程或断电属于强制中断，由下次启动的中断恢复检查统一处理。

## 6. 稳定启动错误

| 错误编号 | 含义 | 处理行为 |
|---|---|---|
| `RUNTIME_DIR_INVALID` | 运行目录不合法、不可创建或不可写 | 停止，不切换备用目录 |
| `PORT_IN_USE` | 已配置端口无法绑定 | 停止，提示关闭占用程序或显式修改本机配置 |
| `INSTANCE_ALREADY_RUNNING` | 同一运行目录已被另一个 PSIT 进程锁定 | 停止，不接触数据库和 GLM |
| `FRONTEND_BUILD_FAILED` | 前端构建命令或产物检查失败 | 停止，不提供旧页面 |

启动失败返回非零退出状态，正常安全关闭返回零。

## 7. 最小验证

- 从项目根目录之外执行 `start.ps1`，仍只产生默认项目根目录下的一套运行数据。
- 使用合法的本机绝对目录覆盖后，数据库、批次、日志和锁全部迁移到该根目录；非法目录停止启动且不回退。
- 默认端口能够启动；占用 8000 后启动明确失败；显式改为可用端口后页面、API 和开发代理使用同一值。
- 同一运行目录启动第二个进程时，第二个进程在数据库迁移和 GLM 调用前失败；强制结束第一个进程后，即使锁文件保留也能重新启动。
- 前端构建失败时启动停止，HTTP 不开放且旧页面不被提供。
- `Ctrl+C` 进入正常关闭流程，关闭后系统锁释放，再次启动可以正常取得锁。
